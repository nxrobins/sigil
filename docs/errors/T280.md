# T280 — Range-for bound is not `i64`

- **Category:** TypeCheck
- **doc_url:** `sigil://errors/T280`

Range-for: both bounds of `for v in a..b` must be `i64` (an integer literal narrows automatically; `arr.len()` on a fixed-size array is accepted directly). Keeping the bounds single-width keeps the loop's compile-time bounds fact a plain i64 comparison — the Z3-free contract the `arr[v]` elision path relies on.
