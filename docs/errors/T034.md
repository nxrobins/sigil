# T034 — Secret-dependent shift amount (CT008)

- **Category:** Effect
- **doc_url:** `sigil://errors/T034`

CT008: `<<` / `>>` by a `@SecretCT` AMOUNT is rejected — a shift by a data-dependent count is variable-time on cores without a barrel shifter and on microcoded shift paths, so the count leaks through timing. Only the right operand (the amount) is checked: shifting a machine-width (`i32`/`u32`/`i64`/`u64`) `@SecretCT` VALUE by a `@Public` amount stays legal, because that latency depends on the public count alone — it is how constant-time code masks and rotates a secret. The exemption is a machine-width statement only: a `u256` `@SecretCT` value shifted by a `@Public` amount passes this rule but is then refused by the formal gate (`I013`) on the `u256_shl`/`u256_shr` lowering, so no `u256` shift touching `@SecretCT` compiles. The check is on the label, so a `let`-copied or arithmetic-derived `@SecretCT` amount is rejected the same way. Make the shift count public data: a literal, a loop index over a `@Public` bound, or a `@Public` parameter, and express the secret-dependent selection with `ct_select` over the constant-count shifts; or step the amount down with `declassify_ct` first if its secrecy is no longer required.
