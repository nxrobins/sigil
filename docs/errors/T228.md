# T228 — Method-level type parameter shadows impl-block-level type parameter

- **Category:** Parser
- **doc_url:** `sigil://errors/T228`

SIGIL Complete v0 / Phase 6: with first-class generic impl blocks (`impl Result<T, E> { ... }`), the impl's `<T, E>` are in scope for every method body. Redeclaring one of them as a method-level type parameter (`fn map<T>(...)`) would silently shadow the impl's binding at dispatch time and break substitution. To fix: either (a) rename the method-level type parameter to a fresh name (e.g., `<U>` instead of `<T>`), or (b) drop the method-level redeclaration if the intent was to refer to the impl's binding (the impl's `T` is already in scope without redeclaration).
