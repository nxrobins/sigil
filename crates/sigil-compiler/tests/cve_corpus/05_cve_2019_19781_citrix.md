# CVE-2019-19781: Citrix NetScaler / Gateway path traversal

**Affected:** Citrix ADC (NetScaler) 10.5, 11.1, 12.0, 12.1, 13.0
**CVE record:** https://nvd.nist.gov/vuln/detail/CVE-2019-19781
**Severity:** CVSS 9.8 (Critical)
**Scope of claim:** STRUCTURAL

## What was the bug

Citrix Application Delivery Controller (ADC), formerly known as NetScaler, is a load balancer and gateway widely deployed at the edge of enterprise networks. Versions 10.5 through 13.0 accepted HTTP requests containing `..` path segments and routed them to the local filesystem without canonicalizing the path.

The vulnerable endpoint was `/vpn/../vpns/cfg/smb.conf`. The leading `/vpn/` was a public, unauthenticated endpoint; the `..` traversal escaped the public scope and landed in the management directory; `/vpns/cfg/smb.conf` was a writable XML configuration file. By writing crafted content to `smb.conf` (and a few related files) attackers could trigger arbitrary command execution as root on the appliance.

## How attackers exploited it

The publicly disclosed PoC:

```
POST /vpn/../vpns/portal/scripts/newbm.pl HTTP/1.1
Host: target
NSC_USER: ../../../netscaler/portal/templates/<arbitrary file>
NSC_NONCE: anything
Content-Type: application/x-www-form-urlencoded
```

This created an attacker-controlled XML template file. A follow-up GET request fetched the template, which the server rendered via Perl's `Template::Toolkit` — Perl code within the template ran as root.

Mass exploitation began in January 2020, weeks after disclosure. Tens of thousands of Citrix appliances were compromised; many became persistent footholds in enterprise networks.

## SIGIL's defense

The Citrix bug existed because a filesystem primitive — open and read an arbitrary path — was reachable from a public unauthenticated endpoint with no gating. The path-canonicalization step that should have rejected `..` segments was missing.

SIGIL's structural defense: filesystem primitives are FFI operations. They require the `FFI` and `Unsafe` effects to be declared in the function's effect row. Inner-ring (default) modules cannot declare functions carrying these effects — they must live in `#[ring(outer)] #[trusted]` modules.

The vulnerable fixture demonstrates the rejection at the declaration site: an inner-ring `read_user_path` function declaring `FFI, Unsafe` effects fires E003. The function declaration itself is the unsafe operation — before any caller can route untrusted input to it.

A correctly-written SIGIL system would put file I/O in a trusted outer-ring module, and the inner-ring caller would have to either go through an actor-message boundary or hold an explicit FsGrant capability (a runtime path-prefix scope). Path traversal is no longer "the parser missed the dot-dot"; it's "the runtime grant doesn't permit that prefix."

## Vulnerable shape

See [`05_cve_2019_19781_citrix.sigil`](05_cve_2019_19781_citrix.sigil).

```sigil
fn read_user_path(path_ptr: i64, path_len: i64) -> i64 ! { FFI, Unsafe } {  // E003 fires
    return host_read_file(path_ptr, path_len);
}
```

## Safe alternative

See [`05_cve_2019_19781_citrix_safe.sigil`](05_cve_2019_19781_citrix_safe.sigil). The file-read function lives in an `#[ring(outer)] #[trusted]` module with its effects explicit.
