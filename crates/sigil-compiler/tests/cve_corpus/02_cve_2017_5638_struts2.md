# CVE-2017-5638: Apache Struts2 OGNL injection (Equifax breach)

**Affected:** Apache Struts2 2.3.x before 2.3.32, 2.5.x before 2.5.10.1
**CVE record:** https://nvd.nist.gov/vuln/detail/CVE-2017-5638
**Severity:** CVSS 10.0 (Critical)
**Scope of claim:** BY-CONSTRUCTION

## What was the bug

Apache Struts2 is a Java web application framework. Its Jakarta Multipart parser handled the `Content-Type` HTTP header by evaluating it as an OGNL (Object-Graph Navigation Language) expression. OGNL is a string-template language with full reflective access to the JVM.

An attacker who controlled the `Content-Type` header — which is to say, any unauthenticated HTTP client — could ship arbitrary Java code into the server's OGNL evaluator. The evaluator had complete access to the running process, including the ability to spawn shells, read files, and exfiltrate data.

This was the bug behind the 2017 Equifax breach. Attackers used CVE-2017-5638 against Equifax's web infrastructure in mid-2017 and exfiltrated personal data for 147 million U.S. consumers. It was one of the largest data breaches in history.

## How attackers exploited it

The canonical proof-of-concept payload:

```
Content-Type: %{(#_='multipart/form-data').(#dm=@ognl.OgnlContext@DEFAULT_MEMBER_ACCESS).
(#_memberAccess?(#_memberAccess=#dm):((#container=#context['com.opensymphony.xwork2.ActionContext.container'])
...
```

The payload evaluates server-side, granting the attacker arbitrary code execution as the web server's user. Once inside, attackers commonly dropped a remote shell or persistent backdoor.

The vulnerability was reported March 7, 2017; mass scanning began the same day. Equifax's compromise occurred between mid-May and late July 2017.

## SIGIL's defense

The Struts2 bug existed because Java's standard library shipped a string-to-code evaluator (OGNL) and the framework wired untrusted input directly into it. SIGIL has no equivalent.

**SIGIL provides no `eval()` of strings, no OGNL-style expression language, no reflection.** The only way for a byte sequence to influence program behavior is through explicit comparison and dispatch — `if header == "multipart/..."` rather than `eval(header)`. There is no point at which untrusted bytes become executable code.

This is a BY-CONSTRUCTION defense: the language lacks the offending feature entirely. A vulnerable SIGIL fixture cannot be written because the dangerous primitive doesn't exist. The corpus has only a safe fixture demonstrating the idiomatic typed dispatch pattern.

## Vulnerable shape

Not expressible in SIGIL. See the SIGIL defense section above for why.
