# `interp/` — an independent SIGIL interpreter

## Why this exists

`docs/CLAIMS.md`'s HB-3 says the trusting-trust bound is now **time, not circularity**, and names
what would close the residue: *a seed whose lineage does not pass through this oracle at all — a
second independent implementation, or a seed reproduced by a third party from source.*

This is that second implementation. Its purpose is one comparison:

```
interpret(S) applied to S  ==  seed/sigil-seed.wasm
```

where `S` is the certified with-driver source. If the committed seed's **binary** contained logic
absent from `S`, an interpreter that only ever does what `S` says would produce different bytes,
and the divergence is the alarm. That is the Thompson threat DDC is built for.

The reason this is tractable rather than a second compiler: **SIGIL's emitter returns the module as
a hex string**. `ai_encode_wasm` produces data, not a code-generation artifact — so this package
needs no WASM knowledge whatsoever. It needs correct semantics for i64 arithmetic, strings,
records, and three container types, and then it can just run the compiler and watch the hex come
out.

## The independence rule (load-bearing — read before editing)

1. **Written from observable behaviour and syntax**, never ported from `crates/sigil-compiler/`.
   The threat model is logic present in a *binary* and absent from *source*; an implementation
   that copies the oracle's code still closes that hole, but one that copies its *binary lineage*
   does not. Keep the derivation clean anyway — it costs nothing and it is unrecoverable later.

   **Stated narrowly, because the looser reading is wrong.** `certified.py` *is* a hand-port — of
   `cap0_input()` / `with_driver_input()` in `crates/sigil-runtime/tests/pipeline_differential.rs`.
   That is the runtime's test harness, not the compiler, so the sentence above holds literally.
   But the input-selection algorithm has exactly one author and one lineage. It decides *which
   source gets compiled*, never what the compiler emits from it, so it is not contamination of the
   result — it is another instance of the shared-misunderstanding class this file already
   discloses. The digest check makes the port's *output* verifiable; it cannot make its *design*
   independent.
2. **The DDC path imports and reads nothing from the Rust tree.** `ddc.py` reads only `.sigil`
   sources and the seed it compares against; the seed is never an *input* to the compile, so the
   artifact under test cannot feed its own verification. No subprocess, no generated code, no
   build step.

   One deliberate exception, scoped to the *differential* and not to the DDC:
   `corpus/golden.json` is generated by `crates/sigil-runtime/tests/interp_corpus.rs` and read by
   `test_differential.py`. That is on purpose — this package cannot run WASM, so it cannot compute
   reference answers, and an implementation that produced its own answer key would be grading its
   own homework. `ddc.py` never touches it.
3. **Standard library only.** Nothing here imports a third-party package: every dependency is
   another lineage. Precisely: the **DDC lane installs nothing**, so the comparison runs against a
   bare interpreter. The `hygiene` lane is different — it `pip install -e "bench[dev]"` for `ruff`
   before invoking these scripts, so "no third-party packages" is not true of *that environment*
   even though no module here imports one. The claim is about imports, and the lane that produces
   the result is clean.

What this does *not* defend against, stated so no one has to rediscover it: a **shared
misunderstanding of the language**. If both implementations read the spec the same wrong way, they
agree and both are wrong. DDC never addressed that class; the differential corpora (Phase 2) do.

## Phase 0 result — the measured subset

Run `python interp/census.py`. It parses exactly what `cap0_input()` composes — the 12 selfhost
modules plus `vec`/`arena`/`string`/`strings`/`option`, **with the same six-function strip list
applied** — and is loud on any construct it does not recognize. A clean run is the evidence that
this inventory is complete.

```
17 files, 26,914 lines, 0 unrecognized constructs
```

| declaration | count |
|---|---|
| functions | 454 |
| methods (in `impl`) | 49 |
| constants | 261 |
| records | 20 |
| `impl` blocks | 16 |
| **enums** | **1** (`Option<T>`) |

**48 syntactic forms**, and the absences matter as much as the presences. The certified source
contains **no** `for` loop, **no** array indexing, **no** `continue`, **no** `&&`/`||`, no
`if let`/`while let`, no array literals, no casts, no match guards, no attributes, no `use`
declarations, and no traits, actors, capabilities or effect declarations. Every loop is a `while`;
every collection access goes through a method call.

Those absences are anti-stubbed. `python interp/test_parse.py` pairs each one with a snippet that
*must* make the parser report it — because a parser that silently swallowed `for` loops would
produce exactly the same census. That test caught a real bug on its first run: `_` lexes as an
identifier, so the wildcard-pattern check never fired and wildcards were being mis-parsed as
one-element paths.

**What the census gate does and does not enforce.** It fails only on a construct the parser cannot
read, so it catches the certified source growing *beyond* the implemented subset — the thing that
would break the DDC path. It does **not** freeze the absence list: the parser and evaluator handle
`for`, indexing, `&&`/`||` and the rest, so adding one to a selfhost source leaves the census
green. The absence table above is a point-in-time measurement, not an invariant.

## What is substituted, and what that cost (settled)

`Vec<T>` is **not** a native container. It is SIGIL code over raw linear memory:

```sigil
record Vec<T> { buf: i64, count: i64, slots: i64, alloc: i64 }
pub fn get(self: Vec<T> @ReadOnly, index: i64) -> T {
    return vec_load(self.buf, index, self.count, self);
}
```

So the true primitive surface is `alloc`, `load8`, `store8`, `vec_load`, `vec_store`,
`str_from_raw` — not the eleven methods the call-site census suggests. Two options:

**Settled: `Vec` alone is substituted.** The evidence it is sound: the Rust oracle and the WASM
selfhost use completely different memory representations and produce byte-identical output, so the
emitted bytes do not depend on allocator addresses.

Everything else executes, including the stdlib string layer, over a **modelled linear memory** —
`alloc` / `store8` / `load8` / `str_from_raw` are implemented as intrinsics (they genuinely are
primitives: `str_concat` calls `a.len()` and `a.byte_at(i)`, so treating *those* as library
functions would be circular).

**This was wrong once, and the correction is the point of the section.** `concat`, `join`,
`bytes_eq` and `itoa` were also substituted, on the assumption they were intrinsics. They are not
— they desugar to `string::str_concat`, `string::str_join`, `string::str_itoa` and
`strings::str_bytes_eq`, ordinary SIGIL bodies inside the certified source, called hundreds of
times including from the emitter. Faking them meant the DDC comparison could not see a
binary-vs-source divergence in exactly that region, while four separate places in the code and
ledger claimed `Vec` was the only substitution. A neutral-framed audit found it on 2026-08-02; the
semantic pins now exercise the real bodies (including `i64::MIN`, the case `str_itoa`'s
negative-space digit math exists to survive).

Generalisable lesson: **substituting more than the evidence demands is not a shortcut, it is a
hole in the result.** Keep the substituted set as small as it can be, and state it in exactly one
voice.

## Layout

| file | role |
|---|---|
| `sigil_lex.py` | tokenizer |
| `sigil_parse.py` | parser — loud on any unknown form |
| `sigil_eval.py` | the evaluator: values, linear memory, intrinsics, method dispatch |
| `certified.py` | composes `S` and verifies it against the pinned digest |
| `ddc.py` | **the comparison**: `interpret(S)` vs the committed seed |
| `census.py` | the measured subset inventory |
| `bench.py` | throughput measurement |
| `test_parse.py` | anti-stubs: every claimed absence has a working detector |
| `test_eval.py` | semantic pins (wrapping, truncating division, reference records, byte strings) |
| `test_differential.py` | the layered oracle differential |
| `corpus/golden.json` | the answer key — Rust-generated, read-only here |

## Status

All five phases are complete: the subset inventory, the vertical slice and its performance gate,
the differential harness, coverage to green, and the DDC comparison itself. `ddc.py` reproduces
the committed seed byte-for-byte.

Where each proof runs, precisely — the distinction matters, because a check that cannot block a
merge is a decoration:

| test | lane | required? |
|---|---|---|
| `interp_ddc_reproduces_the_committed_seed` | `interp-ddc` (parallel, PyPy) | yes |
| `interp_differential_agrees_layer_by_layer` | `test` | yes |
| `interp_ddc_lane_is_wired_in_ci` | `test` | yes |

The DDC lane is feature-gated out of `cargo test --workspace` so it runs in parallel rather than
serialising into `test`'s critical path. That gate is itself fenced: `interp_ddc_lane_is_wired_in_ci`
reads the workflow and fails if no job invokes the target with its feature.

What would strengthen the result is not more code here but **independent authorship** — someone
implementing this from the specification without reading this package, or reproducing the seed
from source on their own machine. See HB-3 in `docs/CLAIMS.md` for the bounds that survive.
